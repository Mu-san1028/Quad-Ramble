# Quad-Ramble

　『QUAD RAMBLE』は、武器やアイテムを使いながら、ルールの異なるラウンドを戦う最大4人の対戦アクションゲームです。
大学のゲーム制作サークルで5人のチームを組み、東京ゲームダンジョン14に出展しました。現在もSteamでのリリースに向けて開発を続けています。
私はチームリーダーとしてこのプロジェクトの開発を進め、プレイヤー操作、遠隔対戦、観戦機能、Botなど、ゲームの主要機能を実装しました。

## ここが面白いぞ！！
### ラウンドごとに立ち回りが変わる！
　武器で相手を吹き飛ばしたり、陣地を取り合ったりと、ラウンドのルールによって得点につながる行動が変わります。
目の前の相手を追うか、陣地を優先するか？それとも早くゴールまで進むか！手に入れた武器やそのときの順位も見ながら、次の一手を考えるのが面白いところです。

### どんどん熾烈になる戦い！
　このゲームでは「疲労度システム」を導入しており、キャラが攻撃を食らうほど吹っ飛びやすくなるようにしています。
UIのデザインもこだわりました。疲労度が高まるにつれて、UIの波が表示領域を覆っていきます。
波の形を保ちながら速度を変え、被弾した瞬間だけ波を乱すことで、普段の疲労の変化と、攻撃を受けた瞬間の両方が伝わるようにしました。

## 工夫したところ
### ラウンド開始の演出を揃える
　オンライン対戦では、次のステージを読み込む時間が端末ごとに異なります。ロードが早い端末から演出を進めると、同じ試合に参加していても、ステージ紹介や開始までの見え方が揃いません。
そこで、全端末の暗転が終わったことを確認してからシーンをロードするようにしました。ロード後も、プレイヤーの配置などの準備が揃うまで画面を暗転させたまま待機します。準備完了後は、暗転を解除する時刻をサーバーが配信し、各端末が共通のサーバー時刻を基準に演出を始めます。全員の準備を待つ処理と、演出を同時に始める処理を分けて実装しました。

[シーン遷移の同期処理](Assets/Scripts/Network/ConnectionContainer.Transition.cs)

### 人間とBotで移動・攻撃の処理を共有
　Botを追加するとき、人間の操作とBotの判断が、それぞれ別の方法でキャラクターを動かす構成だと、移動や攻撃を調整するたびに両方を確認する必要があります。そこで、入力を作る部分と、入力を受け取ってキャラクターを動かす部分を分けました。
人間側はゲームパッドやキーボードの操作から、Bot側はゲーム内の状況に応じた判断から、共通形式の入力を作ります。キャラクター側はその入力を受け取り、共通の移動・攻撃処理を実行します。たとえば攻撃の挙動を調整したとき、その変更を人間とBotの両方に反映できます。

[共通の入力形式](Assets/Scripts/Player/PlayerActionInput.cs) · [Botの制御コード](Assets/Scripts/Bot/BotController.cs)
